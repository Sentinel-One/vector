The `component_sent_bytes_total` metric of every sink now exists from startup with the value 0 and is no longer removed by `expire_metrics_secs` while the sink is idle, so alerts that depend on it, such as a sink that has stopped receiving data, can rely on it being present. The topology builder creates the counter for each sink and keeps it for as long as the sink runs, and each sink counts into it where a send succeeds. The metric now carries only the component tags (`component_id`, `component_kind` and `component_type`): the `protocol`, `endpoint`, `region` and `file` tags were removed, so dashboards and alerts that filter or group by them must be updated. The `aws_s3` and `aws_sqs` sources and the AWS secrets backend no longer expose this metric, because it counted their polling requests and not data. The `file` sink option `internal_metrics.include_file_tag` is still accepted but no longer affects this metric. The stream driver no longer counts bytes (`Driver::protocol` and `DriverResponse::bytes_sent` were removed), so each sink counts the bytes it sends in its own service.
